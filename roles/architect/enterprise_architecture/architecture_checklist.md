One-Page Architecture Checklist (Practical)

Use this before approving or designing any system.

🧠 Foundations

☐ Is the problem clearly defined?

☐ Are trade-offs explicitly documented?

☐ Are decisions recorded (ADR)?

☐ Are views aligned (context, container, component)?

📋 Requirements & Quality

☐ Functional requirements validated

☐ Latency, throughput, availability targets defined

☐ Failure modes identified

☐ Security and compliance requirements known

☐ Cost constraints understood

🧩 Domain & Design

☐ Clear bounded contexts

☐ Ownership boundaries defined

☐ Domain language consistent

☐ Invariants enforced in the domain

🏗 Architecture Style

☐ Style chosen for current constraints

☐ Organizational readiness considered

☐ Operational complexity acceptable

☐ Exit strategy exists

🗄 Data

☐ Data ownership defined

☐ Consistency model chosen intentionally

☐ Backup and recovery planned

☐ Data growth modeled

🔗 Integration

☐ Communication style justified (sync/async)

☐ Failure handling designed

☐ Idempotency considered

☐ Timeouts and retries defined

☁ Infrastructure

☐ Environments clearly separated

☐ IaC in place

☐ Scaling strategy defined

☐ Cost visibility enabled

🔐 Security

☐ AuthN/AuthZ model clear

☐ Secrets management handled

☐ Data protection compliant

☐ Threats reviewed

🚀 Delivery

☐ CI/CD automated

☐ Testing pyramid balanced

☐ Rollback strategy defined

☐ Evolution path planned

📈 Observability

☐ SLIs/SLOs defined

☐ Alerts actionable

☐ Dashboards useful

☐ Incident playbooks ready
